# Test-driven development

**Problem:** changes can ship with tests that merely mirror implementation or never demonstrated the regression.

**Why useful:** this skill makes the failing test and observable seam part of the delivery contract.

**Scope:** behavioural code changes. It does not require every documentation or configuration edit to begin with a failing test.

**Use:** invoke `tdd` for a feature, fix, or refactor, or install this folder through a harness-supported skill location after following [INSTALL.md](../../INSTALL.md).
